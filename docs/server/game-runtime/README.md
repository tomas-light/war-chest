# Игровой runtime server

Игровой контур связывает чистый `@war-chest/game-engine` с PostgreSQL и
transport-адаптерами. База хранит неизменяемую цепочку событий и SQL-проекции,
а память процесса содержит только состояние незавершённых игр и сведения о
текущих Socket.IO-соединениях.

## Границы ответственности

| Компонент        | Ответственность                                                               |
| ---------------- | ----------------------------------------------------------------------------- |
| `GameRepository` | атомарно хранит команды, события и проекции, читает проверенную историю       |
| `ActiveGames`    | хранит live state и соединения, последовательно выполняет операции одной игры |
| `GameService`    | проверяет команды, вызывает engine, применяет события после commit            |
| HTTP и Socket.IO | валидируют transport, выбирают пользователя и отправляют безопасные views     |

Полная цепочка `game_events` остаётся источником истины. `GameState` не
сохраняется отдельным snapshot: при отсутствии игры в памяти service читает
историю по порядку и восстанавливает состояние через `restoreGame`.

## Основные гарантии

- `games.currentVersion` равен `sequence` последнего сохранённого события;
- одна клиентская команда, её события и изменения SQL-проекций фиксируются
  одной транзакцией;
- повторный `commandId` классифицируется до проверки `expectedVersion`;
- live state меняется только после успешного database commit;
- разные игры выполняются независимо, а операции одной игры — последовательно;
- наружу выходят только персональные `GameView` и `GameViewEventData`;
- presence, reconnect deadline и поражение по таймауту входят в persisted
  историю и восстанавливаются после перезапуска.
