# Авторизация по email-коду

War Chest использует один способ входа для всех пользователей: email и
шестизначный одноразовый код. Геолокация, IP-страна, VPN и внешние сервисы входа
не влияют на выбор сценария. После проверки кода сервер создаёт собственную
`HttpOnly` session cookie.

## Пользовательский сценарий

1. Пользователь вводит email. Перед хранением он нормализуется через
   `trim().toLowerCase()`.
2. Сервер создаёт шестизначный код на 10 минут и передаёт его
   `EmailCodeSender`.
3. Пользователь вводит код. Повторная отправка не отменяет ранее созданные
   коды: любой ещё действующий код подходит.
4. Успешная проверка помечает использованными все живые коды этого email.
5. Существующий пользователь получает сессию. Новый пользователь сначала
   указывает обязательный никнейм, после чего получает сессию.

Никнейм не уникален и не используется для входа. Email не публикуется в
профиле.

## Защита от перебора

- повторное письмо можно запросить не раньше чем через 60 секунд;
- на один email действует лимит 5 писем в час;
- на один хеш IP действует лимит 20 писем в час;
- после 5 неверных кодов за час новые проверки временно блокируются;
- в базе хранятся HMAC кода и HMAC IP, а не исходные значения;
- регистрационный билет одноразовый и действует 15 минут;
- ответы auth endpoints получают `Cache-Control: no-store`.

## Development и production

При `APP_ENV=development` адаптер выводит код в терминал server. Браузер код не
получает. Fake backend использует фиксированный код `123456`.

Production-адаптер доставки пока не выбран. Поэтому server намеренно не
запускается с `APP_ENV=production`: перед production необходимо подключить
почтового провайдера, настроить домен отправителя и отдельно проверить
юридические требования к обработке данных и месту их хранения.

## Профиль и аватары

Текущий пользователь может изменить никнейм, удалить аватар, загрузить JPEG,
PNG или WebP до 5 МБ либо выбрать один из preset-аватаров. Загруженное
изображение проверяется, поворачивается по EXIF, обрезается до квадрата,
перекодируется в WebP 256×256 и сохраняется без исходных метаданных.

Каталог preset-аватаров задаётся константой `AVATAR_PRESETS` в
`@war-chest/api-contracts`. Сейчас доступны `archer`, `cavalry` и
`warrior-priest`; новые варианты добавляются в этот каталог без изменения
схемы базы.

## HTTP API

| Метод    | URL                           | Назначение                    |
| -------- | ----------------------------- | ----------------------------- |
| `POST`   | `/api/auth/email/code`        | отправить код                 |
| `POST`   | `/api/auth/email/verify`      | проверить код                 |
| `POST`   | `/api/auth/email/register`    | завершить первый вход         |
| `GET`    | `/api/auth/session`           | прочитать текущую сессию      |
| `POST`   | `/api/auth/logout`            | завершить сессию              |
| `PATCH`  | `/api/users/me`               | изменить никнейм              |
| `PUT`    | `/api/users/me/avatar`        | загрузить свой аватар         |
| `PUT`    | `/api/users/me/avatar/preset` | выбрать preset                |
| `DELETE` | `/api/users/me/avatar`        | удалить любой текущий аватар  |
