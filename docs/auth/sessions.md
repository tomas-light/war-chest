# Пользователи и сессии

После проверки провайдера пакет находит внешнюю идентичность, при необходимости
создаёт пользователя, обновляет аватар и выпускает собственную сессию War Chest.

## Внешняя идентичность

Пользователь ищется по точной паре `(provider, providerSubject)`. При повторном
входе отображаемое имя обновляется, если провайдер вернул новое значение.

Если идентичности ещё нет, пользователь и связь с провайдером создаются в одной
транзакции. Конфликт параллельного создания обрабатывается повторным чтением уже
созданной идентичности. Идентичности разных провайдеров автоматически не
объединяются, даже если у них совпадают email, username или отображаемое имя.

## Создание и проверка сессии

Session token — 32 случайных байта в формате base64url. Клиент получает исходный
token только в подготовленной `HttpOnly` cookie, а в `auth_sessions` хранится
его SHA-256 hash. Срок действия вычисляется из
`AUTH_SESSION_TTL_MINUTES`.

Session cookie имеет:

- имя из `AUTH_SESSION_COOKIE_NAME`;
- `HttpOnly`;
- `Secure` и `SameSite` из конфигурации;
- `Path=/`;
- согласованные `Expires` и `Max-Age`, соответствующие сроку сессии.

`getSession(token)` возвращает пользователя и срок действия только для сессии,
hash которой найден, `revoked_at` не установлен, а `expires_at` находится в
будущем. Вместе с пользователем возвращается текущий hash аватара, чтобы клиент
мог построить версионированный URL.

## Logout

`logout(token)` устанавливает `revoked_at` у ещё не отозванной сессии и
возвращает описание очищенной cookie: пустое значение, `Expires` в начале Unix
epoch и `Max-Age=0`. Повторный logout безопасен и не восстанавливает сессию.
