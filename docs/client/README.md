# Web-клиент

`apps/web` — браузерное React-приложение War Chest. Сейчас это рабочий
технический каркас с первым сквозным игровым сценарием: он переключает real/fake
backend в development-сборке, выполняет вход, показывает незавершённые игры,
создаёт пустую игру, отдельно выбирает и меняет свободное место, подключает
второго игрока, позволяет создателю обменять занятые места, запускает партию и
открывает ожидающую или активную игру зрителю с безопасным snapshot.

Клиент всегда обращается к backend относительно своего origin. Обычные запросы
должны начинаться с `/api/`, Socket.IO использует `/api/socket.io`. В
development и preview эти пути проксирует Vite, а в production их вместе со SPA
обслуживает Fastify.

## Что уже работает

- React 19 и Vite 8;
- маршрутизация React Router в Declarative Mode;
- генерация URL через `nice-web-routes`;
- TanStack Query provider с общей конфигурацией запросов;
- загрузка сессии, защищённые маршруты и logout;
- вход через Google, Telegram и Yandex ID в real-режиме;
- seeded fake-пользователи и сессии из `@war-chest/fake-database`;
- HTTP API adapter для лобби и жизненного цикла игры;
- создание пустой игры, выбор и смена свободного места, подключение второго
  игрока, обмен местами создателем и запуск;
- одно незавершённое участие на пользователя с возвратом в текущую игру из
  лобби;
- публичные аватары в шапке, карточках и игровых экранах;
- отдельный экран активной партии с каркасом поля, игроков, действий и истории;
- единая кнопка открытия игры в лобби, выбор роли внутри ожидающей игры и
  автоматический режим зрителя для уже запущенной;
- live-обновление списка лобби через Socket.IO в real-режиме и
  `BroadcastChannel` в fake-режиме;
- IndexedDB fake adapter для того же сценария без server;
- Zustand-store активной игровой сессии;
- real Socket.IO connection и минимальная fake-реализация;
- development-панель с persisted-переключателем backend;
- SCSS и SCSS Modules;
- локализация интерфейса на русский и английский с выбором языка;
- unit-, component-, fake E2E- и real E2E-тесты.

## Что пока не работает

- HTTP API client для профиля и истории;
- содержимое игрового поля, реальные действия и история ходов после запуска;
- общий `SharedWorker` для последовательной обработки fake-операций из разных
  вкладок;
- просмотр и воспроизведение истории игры.
