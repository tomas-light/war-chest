# React-клиент

Клиент отвечает за интерфейс и удобство игрока, но не принимает окончательных решений о допустимости хода. Он показывает состояние, отправляет команды и применяет подтверждённые сервером события.

HTTP и Socket.IO решают разные задачи: первый работает с аккаунтом и списками игр, второй поддерживает активную партию.

## Предлагаемая структура

```text
apps/web/src/
  config/
  api/
  auth/
  feature-flags/
    feature-flags.store.ts
    feature-flags.provider.tsx
  developer/
    developer-drawer.tsx
  games/
    pages/
    components/
    hooks/
    game-store.ts
    game-socket.ts
  router/
  app.tsx
  main.tsx
```

## Основные экраны

```text
/login
/lobby
/games/new
/games/:gameId
/history
/history/:gameId
```

На `/login` доступны официальный Google button и вход через Telegram OIDC. После входа клиент работает только с собственной сессией War Chest и не хранит токены провайдеров.

На странице игры должны быть видны:

- текущее публичное состояние;
- участники и их статус подключения;
- чей сейчас ход;
- доступные текущему игроку действия;
- состояние отправленной команды;
- понятное сообщение о reconnect или рассинхронизации.

Зритель получает обновления без искусственной задержки, но видит только общедоступную часть поля.

## Синхронизация состояния

При первом подключении клиент получает полный `game:snapshot`. Затем применяет последовательные `game:events`.

Клиент хранит:

- идентификатор игры;
- последнюю применённую версию;
- безопасное представление состояния;
- состояние соединения;
- ожидающие подтверждения команды.

Если пришло событие не следующей версии или восстановить соединение не удалось, клиент запрашивает новый snapshot.

## Feature flags и dev-панель

Feature flags приходят вместе с `GameStarted` и входят в каждый полный игровой snapshot. Значения хранятся в отдельном Zustand store в контексте текущей игры.

Клиент не загружает runtime-файл напрямую и не обновляет флаги во время партии. После reconnect он получает тот же snapshot, который был записан при старте игры.

В development-сборке доступен drawer, где разработчик может переопределить любой флаг. Переопределения сохраняются через Zustand `persist` в `localStorage`.

Drawer показывает серверное, локальное и итоговое значение, позволяет сбросить один флаг или все переопределения. Он отображается только при `developer.panelEnabled: true` и не включается в обычный пользовательский интерфейс production-сборки.

Локальный override управляет только поведением клиента. Он не может включить серверную возможность, выключенную в серверном JSON.

## Порядок реализации

1. Настроить Vite, React и маршрутизацию.
2. Добавить загрузку и проверку `env.yaml`.
3. Добавить HTTP-клиент и конфигурацию адреса сервера.
4. Реализовать вход через Google и Telegram.
5. Реализовать создание игры и присоединение к ней.
6. Подключить Socket.IO-клиент.
7. Получить feature flags из `GameStarted` и сохранить их в контексте игры.
8. Добавить dev drawer и сохранение переопределений.
9. Показать snapshot без игровых действий.
10. Добавить отправку одной тестовой команды.
11. Применять подтверждённые события.
12. Реализовать reconnect и принудительную синхронизацию.
13. Добавить историю и воспроизведение завершённой игры.

Оптимистичные обновления добавляем после надёжной работы подтверждаемого сервером хода.

## Критерии готовности

- две вкладки могут войти в одну игру как разные игроки;
- пользователь может войти через Google или Telegram;
- зритель в реальном времени видит только общедоступное состояние;
- клиент получает feature flags из `GameStarted` или snapshot;
- клиент не меняет базовые значения флагов во время партии;
- dev drawer сохраняет локальные переопределения;
- недоступные действия нельзя отправить через обычный интерфейс;
- после обновления страницы состояние восстанавливается;
- потеря события приводит к полной синхронизации;
- серверная ошибка команды отображается пользователю;
- завершённая партия открывается из истории.
