# React-клиент

Клиент отвечает за интерфейс и удобство игрока, но не принимает окончательных решений о допустимости хода. Он показывает состояние, отправляет команды и применяет подтверждённые сервером события.

HTTP и Socket.IO решают разные задачи: первый работает с аккаунтом и списками игр, второй поддерживает активную партию.

## Предлагаемая структура

```text
apps/web/src/
  api/
  auth/
  games/
    pages/
    components/
    hooks/
    game-store.ts
    game-socket.ts
  router/
  app.tsx
  main.tsx
```

## Основные экраны

```text
/login
/lobby
/games/new
/games/:gameId
/history
/history/:gameId
```

На странице игры должны быть видны:

- текущее публичное состояние;
- участники и их статус подключения;
- чей сейчас ход;
- доступные текущему игроку действия;
- состояние отправленной команды;
- понятное сообщение о reconnect или рассинхронизации.

## Синхронизация состояния

При первом подключении клиент получает полный `game:snapshot`. Затем применяет последовательные `game:events`.

Клиент хранит:

- идентификатор игры;
- последнюю применённую версию;
- безопасное представление состояния;
- состояние соединения;
- ожидающие подтверждения команды.

Если пришло событие не следующей версии или восстановить соединение не удалось, клиент запрашивает новый snapshot.

## Порядок реализации

1. Настроить Vite, React и маршрутизацию.
2. Добавить HTTP-клиент и конфигурацию адреса сервера.
3. Реализовать создание игры и присоединение к ней.
4. Подключить Socket.IO-клиент.
5. Показать snapshot без игровых действий.
6. Добавить отправку одной тестовой команды.
7. Применять подтверждённые события.
8. Реализовать reconnect и принудительную синхронизацию.
9. Добавить историю и воспроизведение завершённой игры.

Оптимистичные обновления добавляем после надёжной работы подтверждаемого сервером хода.

## Критерии готовности

- две вкладки могут войти в одну игру как разные игроки;
- зритель видит только разрешённое состояние;
- недоступные действия нельзя отправить через обычный интерфейс;
- после обновления страницы состояние восстанавливается;
- потеря события приводит к полной синхронизации;
- серверная ошибка команды отображается пользователю;
- завершённая партия открывается из истории.
