# React-клиент

Клиент отвечает за интерфейс и удобство игрока, но не принимает окончательных решений о допустимости хода. Он показывает состояние, отправляет команды и применяет подтверждённые сервером события.

HTTP и Socket.IO решают разные задачи: первый работает с аккаунтом и списками игр, второй поддерживает активную партию.

## Предлагаемая структура

```text
apps/web/src/
  config/
  api/
  auth/
  feature-flags/
    feature-flags.store.ts
    feature-flags.provider.tsx
  developer/
    developer-drawer.tsx
  games/
    pages/
    components/
    hooks/
    game-store.ts
    game-socket.ts
  router/
  app.tsx
  main.tsx
```

## Основные экраны

```text
/login
/lobby
/games/new
/games/:gameId
/history
/history/:gameId
```

На `/login` доступны официальный Google button и вход через Telegram OIDC. После входа клиент работает только с собственной сессией War Chest и не хранит токены провайдеров.

На странице игры должны быть видны:

- текущее публичное состояние;
- участники и их статус подключения;
- чей сейчас ход;
- доступные текущему игроку действия;
- состояние отправленной команды;
- понятное сообщение о reconnect или рассинхронизации.

Зритель получает обновления без искусственной задержки, но видит только общедоступную часть поля.

## Синхронизация состояния

При первом подключении клиент получает полный `game:snapshot`. Затем применяет последовательные `game:events`.

Клиент хранит:

- идентификатор игры;
- последнюю применённую версию;
- безопасное представление состояния;
- состояние соединения;
- ожидающие подтверждения команды.

Если пришло событие не следующей версии или восстановить соединение не удалось, клиент запрашивает новый snapshot.

## Feature flags и dev-панель

При инициализации приложения клиент вызывает:

```text
GET /config/feature-flags.json
```

Этот snapshot хранится в Zustand и управляет общим UI и разделами вне активной партии. Он не обновляется в фоне.

При старте игры feature flags приходят вместе с `GameStarted` и входят в каждый полный игровой snapshot. Игровые значения хранятся отдельно в контексте текущей игры.

Клиент не использует initialization snapshot для игровой механики. После reconnect он получает тот же game snapshot, который был записан при старте партии.

В development-сборке доступен drawer, где разработчик может переопределить любой флаг. Переопределения сохраняются через Zustand `persist` в `localStorage` отдельно для каждого `gameId`.

Drawer показывает серверное, локальное и итоговое значение, позволяет сбросить один флаг или все переопределения. Он отображается только при `DEVELOPER_PANEL_ENABLED: true` и не включается в обычный пользовательский интерфейс production-сборки.

Reload и reconnect одной игры сохраняют её overrides. Переход в другую игру начинает с пустого набора, а выход или завершение партии удаляет сохранённые значения.

## Порядок реализации

1. Настроить Vite, React и маршрутизацию.
2. Добавить загрузку и проверку `env.yaml`.
3. Добавить HTTP-клиент и конфигурацию адреса сервера.
4. Загрузить application feature flags при инициализации.
5. Реализовать вход через Google и Telegram.
6. Реализовать создание игры и присоединение к ней.
7. Подключить Socket.IO-клиент.
8. Получить feature flags из `GameStarted` и сохранить их в контексте игры.
9. Добавить dev drawer и сохранение переопределений.
10. Показать snapshot без игровых действий.
11. Добавить отправку одной тестовой команды.
12. Применять подтверждённые события.
13. Реализовать reconnect и принудительную синхронизацию.
14. Добавить историю и воспроизведение завершённой игры.

Оптимистичные обновления добавляем после надёжной работы подтверждаемого сервером хода.

## Критерии готовности

- две вкладки могут войти в одну игру как разные игроки;
- пользователь может войти через Google или Telegram;
- зритель в реальном времени видит только общедоступное состояние;
- клиент загружает application flags во время инициализации;
- клиент получает feature flags из `GameStarted` или snapshot;
- клиент не меняет базовые значения флагов во время партии;
- dev drawer сохраняет локальные переопределения только для текущего `gameId`;
- overrides не переносятся в другую игру и удаляются после завершения;
- недоступные действия нельзя отправить через обычный интерфейс;
- после обновления страницы состояние восстанавливается;
- потеря события приводит к полной синхронизации;
- серверная ошибка команды отображается пользователю;
- завершённая партия открывается из истории.
