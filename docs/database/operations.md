# Команды и миграции

Корневые команды скрывают расположение workspace-пакета, поэтому для обычной
работы не нужно переходить в `packages/database`.

## Первый запуск

```shell
yarn db:up
yarn db:migrate
yarn db:seed
```

`db:up` запускает PostgreSQL в фоне. Compose healthcheck использует
`pg_isready`; статус можно увидеть через `docker compose ps`.

`db:migrate` применяет ещё не выполненные SQL-миграции. Команду безопасно
запускать повторно: Drizzle хранит журнал применённых миграций.

`db:seed` добавляет двух тестовых пользователей, их внешние идентичности,
тестовую игру, участников, команду и событие `GameCreated`. Идентификаторы
фиксированы, а вставки используют `on conflict do nothing`, поэтому повторный
запуск не создаёт копии.

## Доступные команды

| Команда            | Действие                                              |
|--------------------|-------------------------------------------------------|
| `yarn db:up`       | Запустить PostgreSQL                                  |
| `yarn db:down`     | Остановить контейнер, сохранив именованный volume     |
| `yarn db:generate` | Сгенерировать SQL и metadata из текущей Drizzle-схемы |
| `yarn db:migrate`  | Применить отсутствующие миграции                      |
| `yarn db:seed`     | Добавить идемпотентные тестовые данные                |
| `yarn db:studio`   | Открыть Drizzle Studio                                |

Те же команды доступны напрямую через workspace, например:

```shell
yarn workspace @war-chest/database db:migrate
```

## Изменение схемы

1. Изменить таблицы или ограничения в `packages/database/src/schema`.
2. Выполнить `yarn db:generate`.
3. Просмотреть созданный SQL в `packages/database/migrations`.
4. Применить миграцию к локальной базе через `yarn db:migrate`.
5. Запустить `yarn types:build`, тесты и линтер.
6. Добавить изменение схемы, SQL и Drizzle metadata в один набор изменений.

Сгенерированный SQL не редактируем без причины: Drizzle snapshot должен
соответствовать миграции и TypeScript-схеме. Повторный `yarn db:generate` после
успешной генерации должен сообщать, что изменений схемы нет.

## Остановка и сохранность данных

`yarn db:down` удаляет контейнер и сеть Compose, но оставляет именованный volume
`postgres-data`. Следующий `yarn db:up` подключает его снова, поэтому миграции и
локальные данные сохраняются.

Флаг `-v` удаляет volume вместе с данными и не входит в проектную команду
`db:down`.
