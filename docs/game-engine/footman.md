# Пехотинец

Пехотинец (Footman) использует обычные наём, розыгрыш и движение, но допускает
два отдельных юнита на поле одного игрока. Его тактика позволяет за один жетон
руки последовательно выполнить по одному манёвру каждым юнитом.
В текущем срезе из манёвров доступно только движение; атака и захват остаются
следующими задачами.

## Правила и проверка

Наём берёт жетон из снабжения в открытый сброс и тратит выбранный жетон руки
закрыто, как у остальных отрядов. Розыгрыш занимает свободную контролируемую
точку и создаёт отдельный юнит. `FootmanStrategy` ограничивает число юнитов
пехотинца этого игрока двумя; вражеские пехотинцы не входят в лимит.

Обычное «Движение» перемещает только выбранного юнита. «Тактика» доступна
только при двух собственных пехотинцах на поле. Она содержит ровно два шага
для разных юнитов. Каждый шаг проверяется на свободную соседнюю клетку
относительно результата предыдущего: второй юнит может занять клетку,
освобождённую первым, но первый не может войти на ещё занятую клетку второго.
Владелец, идентификатор и усиления обоих юнитов сохраняются. Дважды переместить
одного юнита вместо двух разных нельзя.

Эти правила сосредоточены в `FootmanStrategy`: лимит юнитов, доступность
тактики, число шагов, запрет повторного манёвра одним юнитом и последовательная
проверка движения. `getUnitTacticOptions` выбирает стратегию по жетону руки,
а она возвращает проекцию поля, доступные следующие цели, число шагов и
признаки возможности сохранения и подтверждения. UI использует эти данные
без собственных правил пехотинца. Схемы API и событий проверяют последовательность
через `isUnitTacticActionValid`, который тоже обращается к стратегии.

## Выбор и черновик

1. Выбрать жетон пехотинца в руке и «Манёвр» → «Тактика».
2. Выбрать первый юнит на поле; у него открывается колесо манёвров.
3. Выбрать «Движение», затем свободную подсвеченную соседнюю клетку.
4. Выбрать второй юнит на поле и его манёвр в отдельном колесе, затем клетку.
5. Подтвердить весь ход.

Колесо каждого юнита сейчас разрешает только движение. Тип манёвра хранится
в каждом шаге отдельно, чтобы дальнейшая реализация атаки и захвата могла
использовать ту же последовательность выбора.

Первый шаг сохраняет приватный черновик и показывает проекцию поля, но
подтвердить её ещё нельзя. Приложение сразу предлагает второй юнит; после
reload восстанавливаются проекция и следующий этап выбора. Отмена удаляет
всю последовательность и возвращает исходное поле и руку. Оппонент и зритель
до подтверждения видят только подтверждённое состояние.

Подтверждение повторно проверяет оба шага через общий движок, тратит один
жетон пехотинца в открытый сброс и один раз завершает ход. Real server и fake
backend сохраняют действие `tactic` с упорядоченным `maneuvers` в одном
`TurnActionPerformed`. История хранит обе цели и показывает оба перемещения.
Промежуточный черновик не попадает в историю и не выполняет случайный добор.

Для выбора переиспользованы существующие колесо, подсветка клеток и панель
черновика. Отдельного составного состояния пехотинца в Figma пока нет;
desktop и mobile оформлены по [визуальному контракту](../ui/README.md).
