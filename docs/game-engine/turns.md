# Цикл ресурсов и пас

Это первый реализованный сценарий полных правил War Chest. Он проходит через
game engine, API contracts, real server, fake backend и игровой стол. Сам пас
пока доступен только в дуэли: командный порядок хода остаётся на согласовании.
Документ описывает только фактически работающее поведение; остальные действия
этапа 6 перечислены отдельно как отложенные.

## Жетоны и начальные ресурсы

`GameCoin` различает два вида жетонов:

| Вид     | Данные                  | Назначение в текущем сценарии       |
| ------- | ----------------------- | ----------------------------------- |
| Royal   | `kind: 'royal'`         | Королевский жетон игрока            |
| Unit    | `kind: 'unit', unitId`  | Жетон выбранного игроком отряда     |

В начальный мешок каждого игрока входят один королевский жетон и по два жетона
каждого выбранного отряда. Поэтому в дуэли мешок содержит 9 жетонов, а в 2×2 —
7. На старте сервер перемешивает мешок и выдаёт три жетона в руку. Порядок
фиксируется событием, поэтому replay не выполняет случайность повторно.

Состояние игрока включает `bag`, `hand` и `discard`. Состояние battlefield
также хранит `round`, начиная с `1`.

## Пас и переход хода

Клиент текущего игрока отправляет `PassTurn` с индексом выбранного жетона
руки. Движок принимает команду только в активной дуэли, от текущего игрока и с
существующим индексом. Результат — одно событие `TurnPassed`.

Выбранный жетон удаляется из руки и попадает в сброс закрыто. Следующим
становится ближайший по очереди участник с непустой рукой. Игроки с пустой
рукой автоматически пропускаются: это цифровая автоматизация обязательного
паса без создания фиктивного события и без поражения игрока.

Если после паса руки всех участников пусты, движок:

1. увеличивает номер раунда;
2. выбирает владельца инициативы первым игроком нового раунда;
3. для каждого участника добирает жетоны до трёх;
4. когда мешок опустел во время добора, перемешивает сброс в мешок и продолжает;
5. оставляет руку меньше трёх, если доступные жетоны закончились.

Сброс не перемешивается заранее, пока в мешке достаточно жетонов для
очередного добора.

## Приватность и восстановление

Внутреннее `TurnPassed` хранит выбранный жетон и итоговый battlefield.
Представление события зависит от получателя:

- владелец видит свою руку, точный счётчик мешка и лица своих закрытых
  жетонов сброса;
- остальные игроки и зрители не получают чужую руку и счётчик мешка;
- закрытый сброс другого игрока содержит только факт наличия жетона без его
  вида;
- публичные данные раунда и текущего игрока одинаковы для всех.

Полный итоговый battlefield входит в безопасное view-событие. Поэтому reload,
reconnect и replay восстанавливают ту же руку, сброс, раунд и очередь без
повторного перемешивания.

## Контракты и версия

- Команда движка и API: `PassTurn { coinIndex }`.
- Событие движка: `TurnPassed`.
- HTTP endpoint real server: `POST /games/:gameId/pass`.
- Fake backend использует ту же команду и тот же движок.
- Версия правил: `GAME_RULES_VERSION = 3`.
- Старые партии удаляются миграциями real и fake баз; аккаунты и сессии не
  удаляются.

## Что ещё не реализовано

Первый сценарий не включает командный порядок хода, перехват инициативы,
наём, розыгрыш, усиление,
перемещение, захват, атаку, способности отрядов, победу по точкам и строки
текущих действий. Он также не меняет пока очередь командного Draft и стартовые
контрольные точки 2×2. Эти возможности должны подключаться отдельными
согласованными сценариями и до реализации остаются недоступными в UI.
